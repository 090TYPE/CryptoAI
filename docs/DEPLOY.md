# Деплой серверного контура CryptoAI

Один VPS. Не две ноды: торговля и боты выполняются на машине клиента, поэтому ни один процесс
здесь не держит `CRYPTOAI_KEK_B64` и изолировать нечего. `CRYPTOAI_ROLE=edge` на `api` закрывает
это не комментарием, а кодом — `/api/secrets`, `/api/2fa` отвечают 503, `/api/trade/*` не
маппится вообще.

Что поднимается: `db` (TimescaleDB) → `api` → `caddy` (TLS) → `worker` (13 коллекторов + AI-джобы)
→ `licensebot` (продажа лицензий) → `backup` (restic в S3).

---

## 0. Что заказывать

| | |
|---|---|
| Провайдер | Timeweb Cloud |
| Локация | Амстердам (ams-1) |
| Линейка | Premium NVMe |
| ОС | Ubuntu 24.04 LTS |
| Конфигурация | 4 vCPU / 8 GB RAM / 80 GB NVMe |
| Публичный IP | 1 шт., IPv4 |
| Оплата | помесячно |

Почему 8 GB, а не 4: в контуре два .NET-процесса, Postgres с TimescaleDB и сборка образов прямо
на боксе (`dotnet publish` в SDK-образе). 4 GB хватит на работу и не хватит на комфортный
`docker compose build`. 4 vCPU — чтобы сборка не занимала десять минут и коллекторы не
конкурировали за процессор с Postgres.

**Про локацию.** У ams-1 задокументированы ~46 ч даунтайма за 61 день (май–июнь 2026, партнёрский
ЦОД). Изначально это считалось блокером из-за платёжных колбэков — сейчас нет: LicenseBot работает
на long-polling Telegram и на этом сервере не стоит вовсе, так что простой площадки не мешает
продавать лицензии и не теряет оплаты. Что реально останавливается на время даунтайма — сбор
свечей, коллекторы и AI-дайджесты. Отсюда следствие: §7 (бэкапы + проверенный restore) —
обязательный шаг, а не отложенный.

Почему 80 GB достаточно: `dex_candles` ограничен политикой retention 30 дней (миграция 020),
сбор идёт только по токенам, которые кто-то держит в избранном. Диск здесь не узкое место.
VPC и второй IP не нужны — это было требование двухнодовой схемы, которой больше нет.

## 1. Первый вход и базовая защита

```bash
ssh root@ВАШ_IP
```

```bash
adduser cryptoai && usermod -aG sudo cryptoai && rsync --archive --chown=cryptoai:cryptoai ~/.ssh /home/cryptoai
```

Ключ вместо пароля, затем в `/etc/ssh/sshd_config`: `PasswordAuthentication no`,
`PermitRootLogin no` → `systemctl restart ssh`. **Проверьте вход новым пользователем во втором
окне, не закрывая текущее** — иначе можно закрыть себе доступ к машине.

Фаервол в панели Timeweb (надёжнее ufw: Docker публикует порты в обход ufw через цепочку
DOCKER-USER): входящие только **22, 80, 443**. Порты 5432 и 8080 наружу не нужны — compose
привязывает их к `127.0.0.1`.

## 2. Домен

A-запись домена → IP сервера. Если через Cloudflare — сначала поставьте **DNS only** (серое
облако): Caddy получает сертификат по HTTP-01, а проксирование Cloudflare этот путь ломает.
Оранжевое облако включайте после того, как сертификат выпущен.

## 4. Код и секреты

```bash
git clone https://github.com/090TYPE/CryptoAI.git && cd CryptoAI && cp .env.example .env
```

```bash
echo "ADMIN_TOKEN=$(openssl rand -base64 32)" && echo "DB_PASSWORD=$(openssl rand -base64 24 | tr -d '/+=')"
```

Впишите обе строки в `.env`, туда же `CRYPTOAI_DOMAIN=api.вашдомен.ru`.

**`DB_PASSWORD` меняется только до первого запуска.** Postgres читает его в момент создания
каталога данных; правка после этого оставит старый пароль в базе и сломает подключение `api`.

Старый `ADMIN_TOKEN` с рабочей машины сюда не переносите — он был выведен в терминал 25.07.

## 4b. Бот продаж

Он в контуре и стартует вместе со всем остальным. Порт не публикует и входящее правило фаервола
ему не нужно: Telegram опрашивается long-polling'ом, Crypto Pay — исходящим HTTPS. Вебхука нет,
поэтому перезапуск или даунтайм площадки не теряет оплату — бот продолжает с последнего update id.

**Ключ подписи.** Он монтируется с хоста, в образ не попадает. С рабочей машины:

```bash
scp .license-signing/private.pem cryptoai@ВАШ_IP:~/CryptoAI/.license-signing/private.pem
```

Каталога после `git clone` нет (`.license-signing/` в gitignore), создайте его до `scp`:
`mkdir -p ~/CryptoAI/.license-signing`. Затем на сервере `chmod 600 .license-signing/private.pem`.

**Ключ должен лежать до первого `docker compose up`.** Иначе бот уходит в цикл перезапусков с
сообщением `License private key missing` — диагностируется мгновенно, но старт вы пропустите.

Этим ключом подписывается любая лицензия на продукт. Он остаётся только здесь и на вашей машине;
в репозиторий он не попадал ни разу (проверено по всей истории), и репозиторий публичный.

В `.env`:

```
BOT_TOKEN=...            # @BotFather
BOT_ADMIN_IDS=...        # ваш telegram id, иначе /stats /recent /issue недоступны
CRYPTOPAY_TOKEN=...      # @CryptoBot → Crypto Pay → Create App. Без него останутся только Stars
CRYPTOPAY_ASSETS=USDT,TON
```

Тарифы и цены — в коде, `BotConfig.DefaultPlans` (Lite 990 ₽ / Pro 2000 ₽ / год 18000 ₽ /
lifetime 40000 ₽). Менять — там, до сборки образа.

Проверка после старта:

```bash
docker compose logs licensebot | tail -5
```

Ожидается `License bot @имя started. Plans: 4. Admins: 1. Stars: XTR. Crypto: on (RUB, USDT,TON).`
`Crypto: off` означает, что `CRYPTOPAY_TOKEN` не доехал. Дальше — `/start` и `/buy` в самом боте.

## 5. Запуск

```bash
docker compose up -d --build
```

Сборка двух образов на 2 vCPU — 5–10 минут. Дальше:

```bash
docker compose ps && curl -s https://api.вашдомен.ru/health
```

Ожидается `{"status":"ok","database":"up",...}`. `degraded` = процесс жив, база нет.

## 5b. Миграции базы при обновлении

Файлы из `db/` смонтированы в `docker-entrypoint-initdb.d`, а этот каталог Postgres выполняет
**только когда каталог данных пуст** — то есть один раз, при самом первом старте. На работающем
сервере новый файл `db/0NN_*.sql` сам не применится: контейнер перезапустится, увидит непустой
`pgdata` и пропустит инициализацию целиком.

Поэтому после `git pull`, который принёс новую миграцию, её нужно применить руками:

```bash
# посмотреть, какие миграции уже в базе (по наличию их таблиц)
docker compose exec -T db psql -U postgres -d cryptoai -c '\dt' | grep -E 'server_settings|dex_candles'

# применить одну миграцию (идемпотентны, повторный запуск безопасен)
docker compose exec -T db psql -U postgres -d cryptoai < db/021_server_settings.sql
```

Порядок важен: миграции нумерованные и рассчитывают, что предыдущие уже применены. Если не
уверены, что применено, а что нет, — прогоните по очереди все, начиная с той, которую точно
ставили последней. Все файлы в `db/` написаны идемпотентно (`IF NOT EXISTS`, `if_not_exists =>
TRUE`), так что повторное применение ничего не сломает.

**Без этого шага** новые настройки просто не появятся: сервер обнаружит отсутствие таблицы,
тихо продолжит работать на значениях по умолчанию и сообщит об этом в `GET /api/admin/settings`
полем `"migrated": false`. Это сделано намеренно — деплой не должен падать из-за непримененной
миграции, — но и заметить проблему без проверки не получится.

## 6. Ключи провайдеров

Через HTTPS, без захода в базу:

```bash
curl -X PUT https://api.вашдомен.ru/api/keys/anthropic -H "X-Admin: ВАШ_ADMIN_TOKEN" -H "Content-Type: application/json" -d '{"apiKey":"sk-ant-...","enabled":true,"note":"prod"}'
```

Так же `coingecko` и `birdeye`. Ключи ложатся в `provider_keys` и подхватываются на следующем
прогоне коллектора — передеплой не нужен.

Без `anthropic` продукт работает, но каждая AI-панель честно сообщает, что ключа на сервере нет:
30 broadcast-потоков, AI-скоринг токенов и `/api/ai/ask` не выдают ничего.

`coingecko`/`birdeye` — это не «опционально», а потолок сбора свечей. `POLL_BATCH=50` при
`POLL_TICK_SECONDS=5` — до 600 запросов в минуту; бесплатный GeckoTerminal отвечает примерно на
30. За несколькими десятками активных токенов начинается 429 и свечи останавливаются (в логе это
видно явно).

Админ-консоль (`CryptoAITerminal.AdminCli`) на сервере не нужна и туда не ставится — она ходит в
Postgres напрямую. С рабочей машины: `ssh -L 5432:127.0.0.1:5432 cryptoai@ВАШ_IP`, затем запуск
консоли локально.

## 7. Бэкапы

Контейнер `backup` стартует выключенным и пишет об этом в лог на каждом запуске. Пока он выключен,
тома `pgdata` и `licensebot_data` — единственные копии двух денежных записей: базы лицензий и
истории заказов бота (кто заплатил, сколько, какой ключ получил).

Бэкапятся оба: `pg_dump` для Postgres и `sqlite3 .dump` для базы бота, каждый своим снапшотом со
своей ретенцией. Если бот на этой машине ещё не стартовал, его база пропускается со строкой в логе,
а не роняет прогон.

В `.env`:

```
RESTIC_REPOSITORY=s3:https://s3.timeweb.cloud/ваш-бакет/cryptoai
RESTIC_PASSWORD=...
S3_ACCESS_KEY=...
S3_SECRET_KEY=...
```

S3 у Timeweb есть только в Санкт-Петербурге — на запись это не влияет (входящий трафик
бесплатный), платный только restore.

`RESTIC_PASSWORD` — это вся защита бэкапа: restic шифрует на клиенте, бакет сам по себе прочитать
дамп не может. Потеря пароля делает все снапшоты нечитаемыми навсегда. Хранить **не на этом
сервере**. Ключу S3 лучше дать права на запись без удаления, чтобы скомпрометированный хост не
стёр историю, которую сам же и загрузил.

```bash
docker compose up -d backup && docker compose logs -f backup
```

**Восстановление ни разу не проверялось.** Проверить один раз, до первой продажи:

```bash
docker compose exec backup restic snapshots
```

Должно быть два пути: `/cryptoai.sql` и `/licensebot.sql`. Дальше — развернуть каждый в пустую базу
и убедиться, что таблицы `orders` и `customers` на месте, а не только что файл скачался.

## 8. Привязка терминала

В приложении: **Settings → CRYPTOAI SERVER** → `https://api.вашдомен.ru` → Save. Файл
`server_url.txt` руками создавать не нужно.

Проверка сквозного пути: добавить токен в избранное → `PUT /api/favorites` → строка в
`tracked_tokens` → резолв пула → свечи.

Только HTTPS. Терминал отправляет лицензию в заголовке `X-License` на каждом запросе — по
плейн-HTTP это открытый токен в канале.

Ключ подписи лицензий (`.license-signing/private.pem`) на сервер не попадает и не должен: сервер
проверяет подпись публичным ключом. Встроенный в код публичный ключ соответствует текущему
приватному, поэтому `LICENSE_PUBLIC_KEY_PEM` можно не задавать — задать придётся, только если
ключевая пара будет заменена.

## 9. Мониторинг

`/health` — процесс и база. Состояние сбора данных:

```bash
curl -s https://api.вашдомен.ru/api/admin/collectors -H "X-Admin: ВАШ_ADMIN_TOKEN"
```

Отдаёт `degraded`, список упавших и список замолчавших коллекторов (порог —
`COLLECTOR_STALE_MINUTES`, по умолчанию 120). Внешний аптайм-монитор нужно вешать на него, а не
на `/health`: коллектор может тихо умереть при полностью живой базе.

Диск: поставить алерт на 80% до первой большой загрузки данных.

## 10. Что остаётся открытым

- **Тарифы не разграничены.** Токен лицензии несёт `Edition`, и ни один эндпоинт сервера его не
  читает. Бот уже продаёт четыре плана по разной цене, а сервис за ними одинаковый: купивший Lite
  за 990 ₽ получает ровно то же, что купивший lifetime за 40000 ₽. На запуск это не влияет,
  но это первое, что надо закрыть после него.
- **Проверенный restore** — см. §7. До первой продажи.
- **Потолок сбора свечей** — см. §6: без ключей CoinGecko/Birdeye за несколькими десятками
  активных токенов начинается 429.
